威脅研究／事件分析

VULONE 報導整理：中國關聯操作者以 AI 代理攻擊亞洲政府

本案打進去的多半不是新零日，而是 Shellshock、2010 年的 JBoss 漏洞、預設帳密、未授權上傳與 SSRF 這類基本問題；AI 的改變在於把枚舉、利用與後滲透的規模與耐心放大。優先檢查：對外管理主控台與預設憑證、老舊元件（JBoss／CentOS／RHEL 年代系統）、檔案上傳與 CGI 端點、SSRF 出口，以及是否有主機曾連往第 3 節的 C2 位址。

分析日期：2026-10-21分類：威脅研究／事件分析原始來源：VULONE Research Team
重要前提：以下「成功存取」數字主要來自操作者自己平台的紀錄。VULONE 只對最強的案例以資料外洩日誌與監聽擷取交叉驗證，並明言受害方逐一確認屬於受害單位通知與執法單位的工作。本整理不把平台紀錄當成受害方已證實的結果。

歸因前提：作者評估為「中國關聯、中文使用者、財務動機」，未在所檢視的證據中發現國家資助證據。不要將 China-linked 直接等同於國家級 APT。

1. 事件摘要

  • 單一操作者（或極小組）自一台新加坡伺服器運行自主利用平台 Cairn，對具名組織發起 66 個專案（2026-09-24 至 2026-10-14）。
  • 48 個至少達到 session 層級存取：root／SYSTEM 6 個、非 root 命令執行 39 個、webshell 階段 3 個；10 個耗盡嘗試未取得存取、1 個失去先前存取、7 個建立但從未啟動。專案 ID 到 120，其中 54 個 ID 不存在，可能為已刪除或重新編號、目標不明。
  • 平台共運行 116 個不重複的 worker 容器；調度日誌 2026-09-24 至 10-06 共 229,828 筆事件（約每 4.5 秒一次，持續 12 天）；單一 LLM 閘道 key 處理約 367.7 億 tokens（36,771,234,882）。
  • 操作者因將主機 /tmp 以無驗證 HTTP 公開（port 9000）長達約 16 天而曝光。VULONE 保存並雜湊驗證共 16.4 GB 證據。

4.4 操作者如何指揮 AI（自平台紀錄還原）

  • 完成標準：「目标必须获取 webshell 或系统命令执行 (RCE)，仅获取后台/应用权限不算完成」——只拿到後台／應用權限不算成功，必須 webshell 或系統命令執行。
  • 手法指示：例如把可用 shell 改為 POST-only 命令提交，使命令走請求內文而非 URL，較不易出現在受害方存取日誌；成功後指示清理證據目錄、使用無害檔案名。
  • 「最高红线」：所有送往目標的內容（URL、標頭、cookie、GET／POST 內文、SQL 與命令 payload）以及寫入受害系統的一切檔案（含腳本、webshell、暫存檔、檔案名、程式註解），必須純英文／ASCII，禁止中文。Worker 會自我檢查 payload 是否符合。這使受害端的語言線索可被製造，防守方應審慎看待語言歸因。
  • 定位：人設定目標與限制、代理負責大部分枚舉／利用／後滲透蒐集。對防守方的含義是：對單一目標的嘗試量與持續性反映的是機器的耐心，不是人的執著。

5. 漏洞與利用手法

5.1 總覽（手法性格）

作者對操作者技術的評價：能組裝出可運作的多代理利用平台，但手法淺——公開利用程式、預設憑證、版本比對為主，沒有原創研究。對防禦良好的目標，則退回憑證路線（如 Huffy 案以管理員 API 權限即完成淪陷，無需 shell）。已具名 CVE 只有兩個，其餘多為設定錯誤、未授權功能與已知弱點類型，原文未給 CVE 編號者本整理不自行補編號。

6. 歸因與相鄰案件區分

  • 單一操作者／極小組（對 C2 基礎設施歸屬）：高信心。
  • 身分：中國關聯、中文使用者、財務動機；工作語言、工具生態與部分金流層（騰訊營運的 LLM 服務、被農場的免費 credits）指向中國。實際位置不明。
  • 國家資助：在所檢視證物中未觀察到——無任務指派、無與已知國家工具共用基礎設施、誘因皆為財務。但政府目標清單本身具國安敏感性，作者提醒不能排除國家行為者對此類存取的興趣。
  • 與「SOUL」活動的區分（Gambit Security 2026 年 9 月底發布）：共用 Cairn 引擎與 DeepSeek v4.1 flash 級模型（工具生態重疊：高信心）；但無共用基礎設施／受害者／資料（同活動：不支持）；同操作者：可能但未證實——SOUL 的標誌性證物（Hermes／Strix 框架、persona 設定、skimming 程式、破壞行為）在本案 16 GB 證據中皆缺席。狩獵時不要將兩案合併。

7. 證據保全（原文作法，供評估可信度）

  • /data/cairn-chat 1.98 GB（74,756 檔案）、主機檔案系統選區 265 MB（12,605 檔案）、容器證據 14.16 GB 壓縮（1,535,238 檔案，含自 Docker overlay 還原的已刪除任務證據約 127 萬檔案、解壓 44 GB）。
  • 全部封存經 gzip 完整性驗證、SHA256 雜湊與時間戳；互動前先保留主機日誌的修改前副本，無可避免的互動皆有紀錄；以可能需在法庭站得住腳的標準處理。
  • 託管主機存取方式原文不公開，僅稱在授權下進行。

8. 一句話防守結論

本案打進去的多半不是新零日，而是 Shellshock、2010 年的 JBoss 漏洞、預設帳密、未授權上傳與 SSRF 這類基本問題；AI 的改變在於把枚舉、利用與後滲透的規模與耐心放大。優先檢查：對外管理主控台與預設憑證、老舊元件（JBoss／CentOS／RHEL 年代系統）、檔案上傳與 CGI 端點、SSRF 出口，以及是否有主機曾連往第 3 節的 C2 位址。
